## 3. 最小可行技术方案

- 一个 itemset 使用 `frozenset` 表示，保证它可以作为字典的 key

- 输出时把 itemset 排序，确保每次运行结果顺序稳定

## 4. 实现流程

### 4.1 读取数据

1. 按行读取数据集。
2. 每一行解析为一个交易。
3. 去掉空白项目。
4. 将每行转换为集合，避免同一个交易中重复项目影响计数。
5. 记录交易总数，用于报告和结果检查。

### 4.2 计算频繁 1-项集

1. 扫描所有交易。
2. 统计每个单独项目出现的交易数。
3. 删除支持度小于 `min_support` 的项目。
4. 得到第一个频繁项集集合 `L1`。

### 4.3 生成候选项集

从上一级频繁项集生成下一层候选项集：

1. 两两合并上一级 itemset。
2. 只保留大小为 `k` 的合并结果。
3. 检查候选集的每一个大小为 `k-1` 的子集是否都属于上一级频繁项集。
4. 如果有一个子集不频繁，就删除这个候选集。
5. 对候选集排序后再参与计数，保持结果稳定。

这一步使用 A-Priori 的核心性质。一个 itemset 如果频繁，那么它的所有子集也必须频繁。

### 4.4 统计候选项集支持度

对每一层候选项集：

1. 扫描所有交易。
2. 判断候选 itemset 是否是交易的子集。
3. 如果是，就把该候选的计数加一。
4. 扫描结束后保留支持度不低于 `min_support` 的候选。
5. 将这一层频繁项集保存起来，供下一轮生成候选集。

当某一层没有新的频繁项集时，算法停止。

### 4.5 生成关联规则，可选

对每个大小至少为 2 的频繁项集：

1. 枚举它的所有非空真子集作为前件 `X`。
2. 用 `itemset - X` 得到后件 `Y`。
3. 计算规则 `X -> Y` 的支持度。
4. 计算置信度 `support(X union Y) / support(X)`。
5. 保留支持度至少为 `s` 且置信度至少为 `c` 的规则。
6. 按置信度、支持度和字典序排序，保证输出可复现。

只有在用户传入置信度参数时运行这一部分。没有传入置信度时只运行必做的频繁项集任务。

## 5. 建议的程序接口

程序暂定使用一个主 Python 文件，并通过 `argparse` 接收参数：

```text
python apriori.py --dataset <数据集路径> --support <整数>
python apriori.py --dataset <数据集路径> --support <整数> --confidence <0 到 1 的小数>
```

建议参数：

- `--dataset` 数据集路径，必填
- `--support` 最小支持度，使用交易数量，必填
- `--confidence` 最小置信度，使用 0 到 1 之间的小数，可选
- `--output-dir` 结果输出目录，可选，默认使用 `results`

程序应在参数错误时给出清晰提示，例如文件不存在、支持度不是正整数、置信度不在合法范围内。

页面没有给出固定的 `s` 和 `c` 数值，所以实现应把它们做成输入参数，并在报告中明确写出实际实验使用的数值。若课程公告或 TA 后续给出指定输入，应以最新要求为准。

### 结果稳定性检查

同一个数据集和同一组参数重复运行时，输出顺序和结果应保持一致。

## 9. 性能检查

基础实现使用集合的子集判断，代码易读，适合本作业的教学目标。A-Priori 的候选剪枝会减少不必要的计数。

需要实际测量：

- 数据读取耗时
- 每一层候选生成和计数耗时
- 频繁项集总数
- 关联规则生成耗时
- 总运行时间
- 程序占用内存是否明显过高

低支持度可能产生大量候选项集，导致纯 Python 实现变慢。先使用课程指定或报告中明确记录的支持度进行测试，再根据实际运行结果决定是否优化。不要在没有测量前加入复杂的数据结构或并行框架。
